# دليل نشر التطبيق على Google Play — الشيف علي اللامي

## 0) ما الموجود
| الملف | الاستخدام |
|---|---|
| `android/` | مشروع تطبيق أندرويد (يعرض موقع المنيو + يفتح واتساب/الاتصال/الخرائط خارجياً + شاشة عدم اتصال) |
| `.github/workflows/android.yml` | يبني APK و AAB تلقائياً على GitHub بدون أي برامج على جهازك |
| `public/privacy.html` ← الرابط `/privacy` | **سياسة الخصوصية** (عربي + إنجليزي) |
| `store/icon-512.png` | أيقونة المتجر 512×512 |
| `store/feature-graphic-1024x500.png` | صورة الميزة 1024×500 |
| `store/screenshot-1..4.png` | لقطات شاشة للهاتف 1080×1920 |
| `tools/make-icons.py` | يولّد كل الأيقونات من شعارك: `python3 tools/make-icons.py logo.png` |
| `upload.jks` + `signing-secrets.txt` (خارج المستودع) | مفتاح التوقيع — **احتفظ به ولا ترفعه** |

الأيقونة الحالية افتراضية (شوكة وسكين). لاستبدالها بشعارك مرّر صورة مربعة PNG للأمر أعلاه ثم ارفع التغييرات.

## 1) الخطوات بالترتيب
1. **Render ← Environment**: أضف المتغير `CONTACT_EMAIL` ببريدك العام للتواصل (يظهر في صفحة الخصوصية)، ثم تأكد أن الرابط يعمل:  
   `https://chef-ali-al-lami.onrender.com/privacy`
2. **GitHub ← المستودع ← Settings ← Secrets and variables ← Actions ← New repository secret**، أضف 4 أسرار (قيمها في `signing-secrets.txt`، وقيمة `KEYSTORE_BASE64` هي محتوى `upload.jks.b64` كاملاً):  
   `KEYSTORE_BASE64` · `KEYSTORE_PASSWORD` · `KEY_ALIAS` · `KEY_PASSWORD`
3. **GitHub ← تبويب Actions ← Build Android (APK + AAB) ← Run workflow**. بعد دقائق افتح التشغيل واحمّل الملف المضغوط `chef-ali-menu-android` من قسم Artifacts، وفيه:  
   - `chef-ali-menu-release.aab` ← **هذا ما يُرفع إلى Google Play**  
   - `chef-ali-menu-release.apk` ← للتوزيع المباشر  
   - `chef-ali-menu-debug.apk` ← للتجربة على جوالك قبل النشر
4. **Play Console** (حساب مطوّر برسم 25$ مرة واحدة، ويلزم توثيق الهوية): Create app ← اللغة العربية ← تطبيق مجاني ← أكمل الصفحات أدناه ← Production ← Create release ← ارفع الـ AAB.  
   - اترك **Play App Signing** مفعّلاً (الافتراضي).  
   - الحسابات الشخصية الجديدة تتطلب **اختباراً مغلقاً بـ 12 مختبراً لمدة 14 يوماً** قبل طلب الإنتاج (شرط من Google للحسابات الشخصية الجديدة؛ راجع Play Console لأي تحديث للشرط).
5. عند كل تحديث للتطبيق شغّل الـ workflow من جديد: رقم النسخة (versionCode) يزيد تلقائياً. أما تعديلات المنيو والأصناف فتظهر فوراً داخل التطبيق دون تحديث.

> بديل بدون كود: موقع **pwabuilder.com** يحوّل `https://chef-ali-al-lami.onrender.com` إلى حزمة Android جاهزة للمتجر (الموقع الآن PWA كامل: manifest + أيقونات + service worker).

## 2) بيانات صفحة المتجر
- **الاسم** (30 حرفاً): `الشيف علي اللامي`
- **وصف قصير** (80): `تصفّح منيو الشيف علي اللامي واطلب وجبتك بسهولة عبر واتساب`
- **الوصف الكامل**:
```
تطبيق «الشيف علي اللامي» يتيح لك تصفّح منيو المطعم بأقسامه وأصنافه وصورها وأسعارها، وإرسال طلبك مباشرة إلى فرعك المفضل.

المزايا:
• فروع متعددة: اختر الفرع الأقرب إليك وشاهد عنوانه وأرقامه وساعات العمل.
• قسم «كل الأصناف» وتصنيفات واضحة، مع الأكثر طلباً والمفضلة.
• اطلب بسهولة: أضف الأصناف، اكتب ملاحظة لكل صنف، اختر منطقتك وسيُضاف سعر التوصيل تلقائياً.
• إرسال الطلب عبر واتساب برسالة مرتبة تحمل رقم الطلب.
• الطلب من الطاولة عبر مسح رمز QR.
• ثلاث لغات: العربية والإنجليزية والكردية.
• تقييم تجربتك والاطلاع على تقييمات الآخرين.
• المنيو يتحدّث فوراً: أي سعر أو صنف جديد يظهر لك مباشرة.

لا يتطلب التطبيق إنشاء حساب.
```
- **الفئة**: Food & Drink (طعام ومشروبات) · **التصنيف**: تطبيق · **مجاني**
- **بريد التواصل**: بريدك العام · **الموقع**: `https://chef-ali-al-lami.onrender.com`
- **رابط سياسة الخصوصية**: `https://chef-ali-al-lami.onrender.com/privacy`
- **رابط/طريقة حذف البيانات** (قسم Data safety): `https://chef-ali-al-lami.onrender.com/privacy#delete`

## 3) App content (محتوى التطبيق)
- **Ads (إعلانات)**: لا يحتوي على إعلانات.
- **App access**: كل الوظائف متاحة بدون تسجيل دخول (لا حسابات).
- **Target audience**: 18 فما فوق (أو 13+)؛ لا تختر فئات الأطفال. **Not designed for children**.
- **Content rating (IARC)**: التصنيف: Utility/Reference أو Lifestyle؛ أجب بـ «لا» على العنف والجنس واللغة والمقامرة والمخدرات؛ لا محتوى يولّده المستخدمون عدا تقييم نصي قصير؛ لا مشاركة موقع. النتيجة المتوقعة: للجميع.
- **News app / COVID / Government / Financial features / Health**: كلها «لا».
- **Permissions**: الإنترنت فقط (ولا حاجة لتصريح الموقع أو الكاميرا).

## 4) Data safety (أمان البيانات) — الإجابات
- هل يجمع التطبيق أو يشارك بيانات مستخدم؟ **نعم**.
- **هل كل البيانات مشفّرة أثناء النقل؟** نعم (HTTPS).
- **هل يمكن للمستخدم طلب حذف بياناته؟** نعم → الرابط: `…/privacy#delete`.
- أنواع البيانات المجمّعة:

| النوع | مجمّع؟ | مشارك مع طرف ثالث؟ | الغرض | اختياري؟ |
|---|---|---|---|---|
| Personal info ← **Name** | نعم | لا* | App functionality | لا (للطلب) |
| Personal info ← **Phone number** | نعم | لا* | App functionality | لا (للطلب) |
| Personal info ← **Address** (عنوان التوصيل) | نعم | لا* | App functionality | لا (للتوصيل) |
| App activity ← Other user-generated content (الملاحظات/التقييم) | نعم | لا | App functionality | نعم |
| الموقع / الصور / جهات الاتصال / المالية / معرّف الإعلانات / Device IDs | **لا** | — | — | — |

\* مزوّد الاستضافة (Render) يعالج البيانات نيابةً عنك كـ «service provider» ولا يُحسب «مشاركة» وفق تعريف Google. واتساب يفتحه المستخدم بنفسه.
